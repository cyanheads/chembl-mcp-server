# 0.4.0 — 2026-10-17

## Added

- **`cursor` / `nextCursor`** on `chembl_get_bioactivities` page a view when a call stages nothing (canvas off, or an inline fit with no `canvas_id`). A cursor page is never staged, and a malformed cursor fails `-32602` before any upstream request ([#17](https://github.com/cyanheads/chembl-mcp-server/issues/17)).
- **Concurrent spill walk:** `chembl_get_bioactivities` fetches spill pages up to `CHEMBL_MAX_CONCURRENT_PAGES` at a time across the server (1–6, default 4) and stages them in offset order, inside the `CHEMBL_SPILL_DEADLINE_MS` budget (10000–600000, default 45000) ([#16](https://github.com/cyanheads/chembl-mcp-server/issues/16)).
- **`truncated_by`** output field on `chembl_get_bioactivities` (`row_cap`, `time_budget`, or `null`) names the bound that cut a staged table short.
- **Installer options:** the Claude Code plugin (`userConfig`), the Codex plugin (`env_vars`), and the `.mcpb` bundle (`user_config`) take the `CHEMBL_*`, `CANVAS_PROVIDER_TYPE`, and `MCP_LOG_LEVEL` settings. The bundle omits the canvas-only ones ([#21](https://github.com/cyanheads/chembl-mcp-server/issues/21)).

## Changed

- **`chembl_dataframe_query` refuses SQL the mcp-ts-core 0.13.15 canvas gate denies** ([mcp-ts-core#729](https://github.com/cyanheads/mcp-ts-core/issues/729)). Calls 0.3.3 answered now fail: `current_setting`, `current_schema`, `current_schemas`, `in_search_path`, `query_table`, and `query()` over anything but a single string literal, or nested more than four deep, as `denied_function`, and a dotted CTE name as `sql_read_only`. `SELECT * FROM query_table('bioactivities')` returned rows on 0.3.3. File reads were already refused on 0.3.3 and now report a different reason: `read_duckdb` fails `denied_function` (was `plan_operator_not_allowed`), and a table reference naming a file fails `sql_read_only`. The gate also lists `parquet_full_metadata` and `parquet_bloom_probe` under `denied_function`.
- **Every tool and resource call holds its upstream requests to a 45 s budget, and a bioactivity spill to `CHEMBL_SPILL_DEADLINE_MS`** ([#33](https://github.com/cyanheads/chembl-mcp-server/issues/33), [#16](https://github.com/cyanheads/chembl-mcp-server/issues/16)). A call 0.3.3 answered after 45–60 s now fails `upstream_timeout`; a spill past its budget stages a truncated prefix (`truncated_by: "time_budget"`).
- **Framework guidance and `devcheck.config.json`** track mcp-ts-core 0.13.15; the README SDK badge tracks ^2.3.1.

## Fixed

- **The potency-ranked spill repeated and dropped tied measurements** at 1,000-row page boundaries. The walk now pages by offset on `-pchembl_value` then `activity_id` ([#32](https://github.com/cyanheads/chembl-mcp-server/issues/32)).
- **Inline `chembl_get_bioactivities` pages** request `min(limit, CHEMBL_MAX_PAGE_SIZE)` rows, not a full 1,000-row page ([#29](https://github.com/cyanheads/chembl-mcp-server/issues/29)).
- **A canvas is minted only when a view spills.** An inline fit, zero match, failure, or cancellation no longer holds a tenant canvas slot, and a spill at the tenant cap fails `canvas_capacity_exhausted` with recovery that names no drop tool ([#28](https://github.com/cyanheads/chembl-mcp-server/issues/28)).
- **A supplied `canvas_id`** has the selected view's table re-staged on every call without `cursor`, inline fits and zero matches included, and a spill onto it that fails or is cancelled leaves the earlier table; the response reports `canvas_id`, `table_name`, and `staged_row_count` ([#31](https://github.com/cyanheads/chembl-mcp-server/issues/31)).
- **An invalid server environment value** fails startup with the framework's configuration banner naming the variable, not a raw stack ([#30](https://github.com/cyanheads/chembl-mcp-server/issues/30)).
- **`chembl_dataframe_drop`** reports a missing or expired canvas as `canvas_not_found` and a reserved-keyword `table_name` as `identifier_reserved`, each with drop-specific recovery; `dropped: false` means no such table on a live canvas ([#26](https://github.com/cyanheads/chembl-mcp-server/issues/26)).
