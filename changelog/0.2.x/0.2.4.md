# 0.2.4 — 2026-08-25

## Changed

- **`@cyanheads/mcp-ts-core` `^0.11.5` → `^0.12.3`** — adopts the MCP SDK v2 migration: `@modelcontextprotocol/server`/`client` replace `@modelcontextprotocol/sdk`, advertised `inputSchema`/`outputSchema` move to JSON Schema 2020-12 with `additionalProperties: false`, and `outputSchema` now declares the error envelope so a strict client validating `structuredContent` no longer rejects a legitimate error result with `-32602`.
- **Tool inputs are strict.** An argument key none of the eight tools declares is now rejected by name (`InvalidParams`) before the handler runs, instead of being silently dropped — a caller's typo surfaces as an error rather than a wrong answer.
- **`MCP_SESSION_MODE` defaults to `stateless`** in `.env.example`, matching the setting the `Dockerfile` already carried — a source run and a container now resolve the same session mode.

## Fixed

- **Docker multi-arch builds no longer crash under QEMU.** The build stage pins `--platform=$BUILDPLATFORM` and drops the now-redundant cross-stage `@duckdb` copy, which would otherwise overwrite the target-platform DuckDB binding the production stage resolves on its own ([#18](https://github.com/cyanheads/chembl-mcp-server/issues/18)).
