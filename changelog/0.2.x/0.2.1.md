# 0.2.1 — 2026-08-12

`chembl_get_bioactivities` closes four gaps: a molecule and target can now be supplied together, the measurements without a derivable `pchembl_value` are reachable for the first time, the canvas spill is bounded and discloses truncation, and canvas guidance points to `chembl_dataframe_describe` before `chembl_dataframe_query`. Framework maintenance and repo hygiene round out the release.

## Added

- **`potency_view`** input on `chembl_get_bioactivities` — `potency_ranked` (default) returns measurements with a derivable `pchembl_value`, most potent first; `null_potency` returns exactly the measurements that have none, previously unreachable because ChEMBL sorts them first under the descending potency sort ([#9](https://github.com/cyanheads/chembl-mcp-server/issues/9)). Each view spills to its own canvas table (`bioactivities` / `bioactivities_null_potency`); querying both against one `canvas_id` and `UNION ALL`-ing them reconstructs the full set. New `contradictory_potency_filter` error when `pchembl_value_min` is combined with `potency_view: "null_potency"`.
- **`CHEMBL_MAX_SPILL_ROWS`** config var (default `50000`) caps the rows `chembl_get_bioactivities` stages to a canvas table, and so the upstream page walk behind it ([#14](https://github.com/cyanheads/chembl-mcp-server/issues/14)). New `staged_row_count` and `truncated` output fields disclose when the cap was hit.

## Changed

- **`chembl_get_bioactivities`** accepts `molecule_chembl_id` and `target_chembl_id` together, narrowing to that one compound–target pair; previously exactly one was required and supplying both raised `missing_filter` ([#8](https://github.com/cyanheads/chembl-mcp-server/issues/8)). The error now fires only when neither is supplied.
- Canvas guidance in `chembl_get_bioactivities`, `chembl_dataframe_query`, and the server's `instructions` now names `chembl_dataframe_describe` ahead of `chembl_dataframe_query` at every mention ([#15](https://github.com/cyanheads/chembl-mcp-server/issues/15)).
- `chembl_dataframe_drop` now wraps with the framework's `disabledTool()` when `CHEMBL_DATAFRAME_DROP_ENABLED` is off — stays visible in the server manifest and landing page with the enable hint, while remaining absent from `tools/list`.
- **`@cyanheads/mcp-ts-core` `^0.10.9` → `^0.11.5`** — `.mcpb` bundling now also strips platform-specific native bindings (`@duckdb/node-bindings-*`) alongside the existing agent-doc strip, keeping the bundle cross-platform and under the registry size cap; `bunfig.toml` gains a Socket supply-chain scanner (`@socketsecurity/bun-security-scanner`); `Dockerfile` adds BuildKit cache mounts and `--omit=peer --ignore-scripts` on the production install stages. Framework scripts and skills re-synced to the 0.11.5 toolchain.
- `tsconfig.json`/`tsconfig.build.json` split so `tests/` are typechecked without shipping in the build output; `.gitignore`'s `data/` entry anchored to `/data/`.
- `.github/SECURITY.md` routes vulnerability reports to `security@caseyjhand.com`; adds `.github/CODE_OF_CONDUCT.md` and `.github/CONTRIBUTING.md`.

## Fixed

- **`chembl_get_bioactivities`** drained the full matching bioactivity set from upstream before returning whenever the canvas was enabled, with no row or page ceiling on the drain — a broad query against a heavily-studied target could trigger dozens of sequential ChEMBL page fetches in one call ([#14](https://github.com/cyanheads/chembl-mcp-server/issues/14)). Bounded by `CHEMBL_MAX_SPILL_ROWS`.
- **`limit`** was silently ignored when the selected view fit inline without spilling — that branch returned every row held by `spillover()`'s character-budget preview buffer rather than the requested `limit`. Now sliced to `limit` on all three response branches (spilled, fit inline, canvas disabled).
