# 0.2.3 — 2026-08-13

`chembl_search_molecules` and `chembl_search_targets` gain cursor pagination, and an identifier-shaped query gets an honest match count instead of a fuzzy-search estimate.

## Added

- **`cursor`** input and **`nextCursor`** output on `chembl_search_molecules` and `chembl_search_targets` — walk past the `limit` cap using the framework's opaque `encodeCursor`/`decodeCursor` pair. `nextCursor` is omitted, never `null`, on the last page; a malformed cursor throws `InvalidParams` (-32602) before any upstream fetch ([#12](https://github.com/cyanheads/chembl-mcp-server/issues/12)).

## Fixed

- **`chembl_search_molecules`** now routes a `query` that is exactly a ChEMBL ID or InChIKey to ChEMBL's single-record lookup instead of the fuzzy `/molecule/search` index, so `totalCount` reflects the real match rather than a full-text relevance count. `max_phase_min` still forces the fuzzy path, and an unknown-but-well-formed identifier returns the existing empty-result shape instead of throwing ([#7](https://github.com/cyanheads/chembl-mcp-server/issues/7)).
- The `similarity` Tanimoto-percent field is now documented as present for `search_type=similarity` results only — the tool description, field `.describe()`, module JSDoc, and a service-layer comment previously implied it on every structure search. No schema or runtime change ([#13](https://github.com/cyanheads/chembl-mcp-server/issues/13)).
