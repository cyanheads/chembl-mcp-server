# 0.6.0 — 2026-11-11

## Added

- **`chembl_get_documents`** resolves a row's or an assay's `document_chembl_id` to its title, authors, journal, year, volume/issue/pages, PMID (as a digit string), DOI, and patent ID. It takes up to 100 distinct IDs per call; misses land in `not_found_ids` and IDs past the cap in `deferred_ids` ([#54](https://github.com/cyanheads/chembl-mcp-server/issues/54)).
- **`chembl_get_drug_info`** gains `withdrawn`, `black_box_warning`, and a `warnings` list with `warnings_status`, `warnings_total_count`, and `warnings_failure`. Both flags are true when any form under the parent carries them, deuterated and isotope-labelled analogs included, and null when the family read failed or was cut short ([#51](https://github.com/cyanheads/chembl-mcp-server/issues/51)).
- **`parent_molecule_chembl_id`, `potential_duplicate` (BOOLEAN), and `bao_label`** on `chembl_get_bioactivities` rows and both staged tables. Filter `potential_duplicate IS NOT TRUE` to keep a null flag ([#53](https://github.com/cyanheads/chembl-mcp-server/issues/53)).
- **`chembl_search_targets`** resolves a ChEMBL target ID sent as `query`, in any case and padded, through `target_chembl_id` ([#48](https://github.com/cyanheads/chembl-mcp-server/issues/48)).

## Changed

- **Breaking: `chembl_get_assay` takes `assay_chembl_ids` and returns `assays[]`** ([#55](https://github.com/cyanheads/chembl-mcp-server/issues/55)). Input `assay_chembl_id` (string) becomes `assay_chembl_ids` (1–1,000 IDs, the first 100 distinct looked up). Output: the eight top-level assay fields move into `assays[]`, beside `not_found_ids` and `deferred_ids`. A single miss is now a success with the ID in `not_found_ids`, where it was `-32001 not_found`. The singular key still works through `inputAliases`, but a client that validates arguments against the advertised schema refuses the 0.5.0 call shape. Migrate: send `assay_chembl_ids`, read `assays[0]`.
- **`chembl_dataframe_query` no longer drops rows from `content[]` past a 40,000-character budget**, and the `rendered_rows` output field is removed. Every row the SQL returns renders; size the result with `LIMIT` ([#52](https://github.com/cyanheads/chembl-mcp-server/issues/52)).
- **The staged bioactivity tables have 27 columns**, with the new ones at positions 4, 11, and 23: a positional `SELECT *` reader sees the later columns shift ([#53](https://github.com/cyanheads/chembl-mcp-server/issues/53)).
- **`chembl_search_molecules` applies `max_phase_min` to similarity and substructure searches**, and to an exact search by its hit's own phase ([#50](https://github.com/cyanheads/chembl-mcp-server/issues/50)). ChEMBL filters only the first 30,000 substructure hits, so an unfiltered count flags `totalCountCapped` with a lower-bound notice when that ceiling cuts the filter.
- **`chembl_search_molecules`** honours a cursor offset on an exact search and names an input its `search_type` ignores (`query`, `structure`, or a non-default `similarity_threshold`) in the notice. The `max_phase` description says a withdrawn drug keeps 4, and the zero-hit advice names only what each `search_type` can change ([#50](https://github.com/cyanheads/chembl-mcp-server/issues/50)).
- **`chembl_get_bioactivities` reads a blank `canvas_id` or `potency_view` (`""`, whitespace) as omitted**, and the advertised schema admits the blank. The dataframe tools still require a real `canvas_id` ([#45](https://github.com/cyanheads/chembl-mcp-server/issues/45)).
- **`chembl_get_drug_info`:** `max_phase` and `first_approval` stay the queried form's own record; their descriptions now say so, and the text output's `Parent:` line states which values are the form's own and which cover the family ([#51](https://github.com/cyanheads/chembl-mcp-server/issues/51)).
- **`chembl_get_assay` and `chembl_get_documents`:** a 404 on their one list request is `upstream_unavailable`, not a `not_found` telling the caller to verify the ID.
- **`chembl_get_bioactivities` zero-hit notice** names every filter sent, organism first (steering `human` to `Homo sapiens`), and on a one-form molecule call suggests `include_alternate_forms: true`.
- **`chembl_get_bioactivities` inline preview budget** is 900 characters per row, up from 800, since the new fields widened rows by about 100. The fit-vs-spill line moves by up to about two rows of `limit` in either direction.
- **`chembl_get_bioactivities` with the canvas off** says whether more rows of the view remain past the page, where it said "capped preview" even when the whole view fit.
- **`chembl_search_targets` zero-hit notice** names every filter sent ([#48](https://github.com/cyanheads/chembl-mcp-server/issues/48)).
- **`confidence_score` description** states ChEMBL's 0–9 scale ([#55](https://github.com/cyanheads/chembl-mcp-server/issues/55)).
- **SQL examples** in the spill notice and the `chembl_dataframe_query` description group on `parent_molecule_chembl_id` with `potential_duplicate IS NOT TRUE`.
- **Startup loads `.env` through `process.loadEnvFile()`.** An invalid framework env value, in the environment or `.env`, prints the config banner and exits 1 instead of a raw stack ([#47](https://github.com/cyanheads/chembl-mcp-server/issues/47)).
- **`skills/chembl-guide` 1.0 → 1.1** (`skill://chembl-guide/SKILL.md`): the new tool and batch assay reads in Scope and Identifiers, Gates 3, 4, 5, 8, and 9, the drug workflow, the DataCanvas alias rule, and the SQL recipes.
- **The DataCanvas runs on DuckDB 2** (`@duckdb/node-api` ^2.0.0-r.1). `chembl_dataframe_query` SQL executes on the new engine.
- **Canvas SQL refusals** — mcp-ts-core 0.13.19. A statement naming a file is `sql_read_only`, a parsed non-SELECT is `non_select_statement`, and every `pragma_*` function is `denied_function`. `SHOW <table>` answers.
- **`canvas_capacity_exhausted` hint** says to reuse a held `canvas_id` or retry once idle canvases expire, and no longer names a drop tool — mcp-ts-core 0.13.19 ([#748](https://github.com/cyanheads/mcp-ts-core/issues/748)).
- **Canvas SQL error recovery hints** follow the engine's error class, and a `Binder Error` is `ValidationError` with `reason: 'sql_execution_error'` — mcp-ts-core 0.13.19–0.13.20.
- **The tool-error trailer gains `retry after <value>`** on `rate_limited` — mcp-ts-core 0.13.19 ([#627](https://github.com/cyanheads/mcp-ts-core/issues/627)).
- **`createApp()` exits 1 on Node below 24**, and Bun must be `>=1.4.4` — mcp-ts-core 0.13.20–0.13.22. `engines.bun` rises to match.
- **`MCP_PUBLIC_URL` and `MCP_HTTP_ENDPOINT_PATH` are validated at startup**, and an unusable value stops it — mcp-ts-core 0.13.21 ([#830](https://github.com/cyanheads/mcp-ts-core/issues/830), [#831](https://github.com/cyanheads/mcp-ts-core/issues/831)).
- **Argument-repair rejections report the failed `.min()`/`.max()` check**, and captured upstream error bodies stay off client envelopes — mcp-ts-core 0.13.22 ([#745](https://github.com/cyanheads/mcp-ts-core/issues/745), [#590](https://github.com/cyanheads/mcp-ts-core/issues/590)).
- **Framework guidance, scripts, and `.env.example`** track mcp-ts-core 0.13.22. `clean-mcpb` and `lint-packaging` now carry the fix that keeps the MCP SDK's `dist/ext/skills/` modules in the `.mcpb` ([mcp-ts-core#794](https://github.com/cyanheads/mcp-ts-core/issues/794)), replacing the local one, and `.env.example` lists `MCP_JWT_EXPECTED_AUDIENCE` and `MCP_JWT_EXPECTED_ISSUER`.
